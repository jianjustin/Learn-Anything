# 追加题目流程

学习者给你一份新的真题（某年某卷的某个模块），或者说「把 xxx.pdf 内的题目加入到课程内」时，按本文把题目收进**仓库里的**真题库，再同步到对应的课程。流程共七步，每一步都有要用的命令或字段。`<国考题库>`、`<题库>`、`<skill 目录>`、`<课程文件>` 的含义见 TEMPLATE.md「题库在哪」；**模块 slug** 记作 `<slug>`（如 `xingce-shuliang`）。

题库只有一份，就在 `<国考题库>` 这个 git 仓库里。这个流程改的是仓库里的题库文件，这是学习者要的「题库只留一份」；课程这边只靠 `guokao.mjs sync` 从仓库同步，不手改。

真题库的两个文件，格式以现有的 `<题库>/zhenti/<slug>.md` 和 `<slug>.data.js` 为准，先读该模块 md 的开头说明和三道题再动手（该模块还没有 `<slug>.md` 时，先按下文「为新模块起一个 `<slug>.md`」建好文件头）：

- `<题库>/zhenti/<slug>.md`：人读的题库。每题一个条目 `### {行标签}-{题号}`，字段行依次是 `- 题型：`、`- 次题型：`（可选，复合题才写，见第 3 步）、`- 考点：`、`- 资料：`（数量关系库没有这一行，其余模块每条必填，见第 3 步）、`- 用途：`、`- 参考答案：`、`- 独立解：`、`- 一致：`、`- 来源：`、`- 题图：`，然后是 `#### 题干`（代码块）、可选的 `- 备注：` 行（写在题干代码块之后，见第 2 步）和 `#### 解法`。
- `<题库>/zhenti/<slug>.data.js`：由 md 生成的机器可读片段，**不要手改**。

行标签（条目标题 `###` 后的前半段）通常是年份，如 `2021`；同一年有多套卷时用卷名，如 `2024地市`、`模拟卷一`。它同时是课程「真题覆盖」表里的一列。

## 七步流程

### 1. 确认来源

向学习者确认或自己查清四件事，缺一不可开工：

- 哪一年、哪套卷（副省级 / 地市级 / 模拟卷）、哪个模块（对应 `<slug>`）。
- 题本 PDF 的完整路径，和题号范围（例如「第三部分 数量关系」第 61–75 题）。
- 答案解析 PDF 的完整路径。没有答案的卷不收（没有参考答案就没法核对独立解）；答案缺失就停下来问学习者。
- 来源标签，即行标签（条目标题 `### {行标签}-{题号}` 里的前半段，如 `2021`；它同时是课程「真题覆盖」表里的一列）。

题本和答案常在同一个资料目录的两个兄弟文件夹里（`行测-真题/` 与 `行测-答案及解析/`）。`- 来源：` 里的路径用 `$R` 简写，`$R` 的定义和页码口径沿用该 `<slug>.md` 开头的说明。

**已知问题**：2023 年国考副省级的题本 PDF 是损坏的，打不开；2023 年一律改用《冲刺套卷（5年真题+3年模拟）（行测）》PDF 里收录的 2023 副省级真卷（具体页码见 `<题库>/zhenti/xingce-shuliang.md` 开头和 2023 各条目的 `- 来源：`）。遇到别的打不开的题本，同样先找替代来源，并在条目 `- 来源：` 里写明实际取自哪份文件。

### 2. 提取题干

按题号范围找页码，再提取文字：

```bash
pdftotext -layout -f <起始页> -l <结束页> "<题本.pdf>" -
```

页码一律用 PDF 物理页（`-f` / `-l` 用的页号），不是页脚印刷页码，`- 来源：` 里也写物理页。

`pdftotext -layout` 可能丢字、错位，尤其是上下标、根号、分数、带图的题；提取完必须对照原页核对。渲染一页成图再看：

```bash
pdftoppm -r 110 -f <页码> -l <页码> -png "<题本.pdf>" <输出前缀>
```

有题图的题：把图裁剪后存成 `<题库>/zhenti/img/<行标签>-<题号>.png`（证监会卷与国考卷的年份行标签会重名，计算机、证券期货题图改用 `img/<slug>-<行标签>-<题号>.png`；行标签含中文的地市卷用 `img/<年份>ds-<题号>.png`），条目里写 `- 题图：img/<行标签>-<题号>.png`，并在题干代码块里用一行 `【图】…` 把图的内容转写成文字；没有图写 `- 题图：无`。选项里的公式若在原卷里是图片，按图转写，并在题干代码块之后加一行 `- 备注：选项在原卷中为公式图片，此处按图转写。`。编者注一律写在 `- 备注：` 行，不放进题干代码块。

### 3. 归类

给每题定 `- 题型：`（节点 id）和 `- 考点：`（一句话，例如「盈亏问题列方程」）。**题型 id 必须用该课题型地图已有的节点 id**（见 `<题库>/outlines.data.js` 里该 `<slug>` 的 `typemap.nodes`，或课程考情课里的「题型地图」表）；不同模块的 id 可能同名但含义不同（如常识判断的 `jingji` 是经济常识，数量关系的 `jingji` 是经济利润），只看本课的节点。`zhenti-data.mjs` 按 `<slug>` 从 `outlines.data.js` 取节点的 `label`、`methods`，题型不是该课大纲的节点 id 就报错。以 `xingce-shuliang` 为例，节点 id 与 `label`、`methods` 的对应关系（与 `outlines.data.js` 一致）：

除数量关系外，每题在 `- 考点：` 之后还要写一行 `- 资料：`：题目所依赖的原文、法规（写到条款）、学科领域或统计材料，多项用分号分隔，格式沿用该模块 md 开头的口径（如「立法法（2023 年修正） · 第十、十二条」「政论：调查研究」「科技说明文：植物声学」「国家统计局：京津冀 2013–2022」）；未逐字核对原文的出处标「待核」。文件头的 `## 资料列表` 把全部条目的 `- 资料：` 去重汇总（每行写题数和题号），追加题目后同步更新。`zhenti-data.mjs` 不读这一行，它只留在 md 里。

| id | label | methods |
|---|---|---|
| `fangcheng` | 方程与比例 | 设未知数 · A 和非 A 思想 · 排比句 · 鸡兔同笼 |
| `paizu` | 排列组合与概率 | 分类分步 · 捆绑插空 · 平均分组 · 描点法 · 古典概率 |
| `jihe` | 几何 | 面积体积 · 相似比 · 勾股 · 切长最短 |
| `xingcheng` | 行程问题 | 相遇追及 · 等距离平均速度 · 多次相遇 · 漂流瓶 |
| `zuizhi` | 最值与统筹 | 最不利构造 · 最值思维 · 统筹安排 |
| `gongcheng` | 工程问题 | 赋值总量 · 暑假作业型 · 同时开始同时结束 |
| `jingji` | 经济利润 | 成本售价 · 利润率 · 合并付费 |
| `zhouqi` | 周期与日期 | 星期推算 · 找周期 · 余数定位 |
| `dengcha` | 等差数列 | 通项与求和 · 中项 · 等差数列中的倍数特性 |
| `rongchi` | 容斥原理 | 两集合 · 三集合公式 · 常识公式 |
| `nianling` | 年龄问题 | 年龄差不变 · 同增同减 · 比例设份数 |
| `rongye` | 溶液问题 | 溶质守恒 · 混合浓度 · 十字交叉 |

归类口径同 `<slug>.md` 开头：`jingji` 只用于涉及成本、利润、折扣、售价与利润关系的题，单纯「单价×数量」列方程归 `fangcheng`；多工序、多人分工求最少时间的统筹题归 `zuizhi`，不归 `gongcheng`；日期星期与循环周期归 `zhouqi`，等差数列归 `dengcha`，以年龄为核心量的归 `nianling`。数量关系的「倍数特性与代入排除」（`beishu`）、「复合题：拆成两步」（`fuhe`）是方法课，不是节点，不能作 `- 题型：`。

**次题型（可选）**：一道题除主模型外**还必须**用到第二个模型或工具才能解出时（复合题），在 `- 题型：` 之后紧接着加一行 `- 次题型：<id>`，并在 `- 考点：` 里写明理由（如「百分数整除定倍数；次题型 beishu：A=13B/20，B 必须是 20 的倍数」）。值是本课题型地图的节点 id 或 `beishu`，不能与题型相同；只是顺手列一个方程、做一次简单比较的不写。判断时逐题读题干和自己的独立解，不凭考点一句话猜。`zhenti-data.mjs` 把它输出为 `items[].type2`，不计入 `count`；数量关系的组合对统计在 `<题库>/shuliang-models.md` 第 14 节，标了新的次题型后同步更新那张表。

**什么时候才能新增题型节点**：先逐个看现有节点，确认没有一个合适，才新增。新增时要同时做三件事：

1. 在 `<题库>/outlines.data.js` 该 `<slug>` 的 `typemap.nodes` 里加一个节点（`id`、`label`、`methods`、`lesson`；`lesson` 指向该大纲 `lessons` 里存在的课，没有就在大纲里同时加一课），否则生成 `data.js` 会报错；
2. 课程这边**不手加节点**：第 6 步的 sync 会按仓库大纲把新节点补进课程。但节点的 `lesson` 必须是课程里**确实存在**的课，否则 sync 报错、课程不动。所以仓库大纲里新节点指向的是新加的课时，先照通用的「调整大纲」在课程里插入同一个 id 的课（`status: "todo"`、`mastered: false`、`readings: []`、`cards: []`），校验通过再跑 sync；
3. 把新增的节点和理由告诉学习者，不要悄悄改动题型地图。

### 4. 独立解与核对

每题自己独立求解一遍，不先看答案解析，得到 `- 独立解：`；再从答案解析 PDF 里读出 `- 参考答案：`（格式 `B（<答案文件名> 第 N 页）`）。两者相同写 `- 一致：是`；不同写 `- 一致：存疑`，并在 `#### 解法` 里写清楚你的推导和分歧点，**不要**为了凑一致而改答案。参考答案是培训机构整理的，不是官方答案。`#### 解法` 里写简明的解题步骤，不是答案解析的抄录。

**答案 PDF 是扫描件时**：`pdftotext -layout` 输出为空或只有页眉，就是扫描件（没有文字层，如 2021 年副省级答案解析 PDF 第 1 页之后）。这时先把全部页渲染成缩略图，看图定位答案所在页，再把那一页渲染清楚读图核对：

```bash
pdftoppm -r 50 -png "<答案.pdf>" <缩略图前缀>                      # 全部页缩略图，找答案在哪页
pdftoppm -r 110 -f <页码> -l <页码> -png "<答案.pdf>" <输出前缀>   # 该页读图核对
```

读不到参考答案时停下来问学习者，不要猜；此时 `- 一致：` 不得写「是」，写「待核：答案 PDF 为扫描件，未读到」（这类题同 `存疑`，不作示范、不作变式蓝本、不进组练）。

`- 用途：` 默认写 `demo`（供课内示范）。只有学习者明确说「留作整卷」「留作模考」的题才写 `hold`；`drill` 供组卷练习，学习者要求才写。拿不准就问，不要自己把题标成 `hold`。

### 5. 追加数据文件

把新题条目追加到 `<题库>/zhenti/<slug>.md` 末尾（保持 `### {行标签}-{题号}` 的格式和字段顺序，一年内按题号升序）。新行标签（2021、地市卷、模拟卷等）**不改** md 开头的「分布」表和「2027 侧重推断」——那两处只统计 2024–2026 副省级（固定的「近三年」窗口），表的列也是固定的；只有补回 2024–2026 副省级的缺题，才更新表里和推断里受影响的数字。同时把开头第一段里「收录 …」那一句补一行，列出新增的来源（如「另收录 2021 副省级」）；有 `## 资料列表` 的模块把新题的 `- 资料：` 并进去，开头「核对结论：存疑 N 题、待核 M 题」一行按新增的存疑、待核题更新。改完 md 后运行：

```bash
node <国考题库>/guokao-sprint/scripts/zhenti-data.mjs <slug>
```

它由 `<slug>.md` 重新生成 `<slug>.data.js`，不要手改 `data.js`。生成后检查：`years` 含新行标签、`items` 里每个新题都在、有题图的带 `img`、`drill`/`hold` 标记符合 `- 用途：`、`nodes[].count` 与 md 里的题数吻合（`count` 是固定的「近三年」窗口，键恰好是 `"2024"`、`"2025"`、`"2026"`，没有题补 0；2021、卷名之类的其他行标签只进 `years` 和 `items`，不进 `count`）。题型不是该课大纲（`<题库>/outlines.data.js`）的节点 id、缺字段、题号重复，脚本会报错并退出，按提示改 md。

### 6. 同步到课程

课程不手改，跑同步：

```bash
node <skill 目录>/scripts/guokao.mjs sync "<国考题库>" "<课程文件>"
```

它从仓库重新取题型数、新增的题型和真题清单，写进课程的 `templateData.growth`，重写考情课末尾的「题型地图」「真题覆盖」两张表格卡；已示范的标记保留，学习进度不动。`hold` 题的题图不会进课程文件。

- 输出 `nodes=… items=… demo=…` 是同步后的题型数、真题数、已示范数，核对新题都进来了。
- △ 行：补进了新题型、或丢掉了题库里已没有的题的「已示范」标记，转告学习者。
- ✗ 行（退出码 1）：课程文件没动。常见原因是新题型在仓库大纲里找不到，或它指向的课不在课程里（回到第 3 步）；`.data.js` 读不懂就回第 5 步重新生成。把信息原样告诉学习者，不手改课程文件绕过去。

课程还不存在时，不要手搭，运行 `node <skill 目录>/scripts/guokao.mjs new "<国考题库>" "<课程目录>" <slug>`，它按仓库大纲和 `<slug>.data.js` 直接建出带两张表格卡的课程。

### 7. 校验与提交

```bash
node <skill 目录>/scripts/validate.mjs "<课程文件>"
```

退出码 0 才算完。仓库里有 `tests/` 时，在 `<国考题库>` 下运行 `node --test tests/unit`，确认库内测试仍通过。

追加的题目是 **guokao_sprint 仓库里被 git 跟踪的改动**：`guokao-sprint/references/zhenti/<slug>.md`、`<slug>.data.js`、新的 `guokao-sprint/references/zhenti/img/*.png`（新增节点时还有 `guokao-sprint/references/outlines.data.js`）。在 `<国考题库>` 里**按文件名** `git add` 这些文件并 `git commit`（提交信息如「zhenti: 追加 2021 副省级数量关系」），不用 `git add -A`：仓库里可能还有学习者自己没提交的改动。要提交的文件在追加之前就有学习者没提交的改动时，先问学习者再提交。不能执行 git 时，提醒学习者自己提交。

然后把「加了哪些题、归了哪些题型、有几题独立解与参考答案不一致、有没有新增节点」用一段话告诉学习者。

## 为新模块起一个 `<slug>.md`

`<题库>/zhenti/` 下还没有该模块的 `<slug>.md` 时（行测六模块、申论（`shenlun-quanjuan`）、计算机（`computer-zhuanye`）、证券期货（`finance-jichu`）都已有；新模块只会出现在大纲新增 slug 时），先建文件、写好下面这段最小头部，再按第 5 步在末尾追加条目。`<slug>` 必须是 `<题库>/outlines.data.js` 里的模块，文件名就是 `<slug>.md`：

```markdown
# 国考<科目> · <模块名>真题库（<卷别>）

本文件收录国考<科目><卷别>卷<模块名>部分的真题：<年份> 年为「第 N 部分 <模块名>」第 <起>–<止> 题。逐题给出题干与选项、题型归类、参考答案、独立解与核对结论。题干取自真题题本 PDF，参考答案取自配套的答案解析 PDF；**参考答案为培训机构整理，非官方公布答案**，每题另附本库独立求解结果，二者不一致处标「存疑」。路径简写：`$R` = `<资料根目录的绝对路径>`；页码一律为 PDF 物理页（`pdftotext -f` 所用页号），不是页脚印刷页码。题型归类口径：题型 id 用 `references/outlines.data.js` 里 `<slug>` 的 `typemap` 节点 id，<易混题型怎么归，一句话>。用途：`demo` 供课内示范，`drill` 供组卷练习，`hold` 留作模考。

<!-- 分布：首次有 2024–2026 数据后再补 -->
```

- 「分布」表和「2027 侧重推断」只统计 2024–2026 副省级；还没有这三年的题时只留上面那行注释，不编数字。
- 有了 2024–2026 的题后，文件头依次是：说明段、「核对结论：存疑 N 题、待核 M 题，见各条目。」一行、`## 分布`、`## 资料列表`、`## 2027 侧重推断`、`## 可粘贴片段`（参照现有的 `<题库>/zhenti/xingce-ziliao.md` 等）。文件头里的分组标题用加粗文字，不要用 `###`——`###` 只留给条目。
- 来源段里的 `$R` 写到资料根目录为止，条目 `- 来源：` 里的路径都用它简写。
- 建好后照常走第 5 步：追加条目，运行 `zhenti-data.mjs <slug>` 生成 `<slug>.data.js`。

## 提示词模板

学习者可以把下面的内容整段复制，替换 `<…>` 后发来：

```
请将 <年份> 年国考行测 <卷别> 的「<模块名>」真题加入到课程内（模块 slug：<slug>）。

- 题本：<题本 PDF 完整路径>，题号 <起> 到 <止>
- 答案解析：<答案解析 PDF 完整路径>
- 来源标签（即行标签）：「<来源标签>」
- 用途：<demo 或 hold 或 drill；没说就默认 demo>

按 guokao 模板的追加题目流程做：提取题干并对照原页核对，归到现有题型（没有合适的先问我再新增节点），每题先独立求解再对照参考答案，追加到题库仓库的 zhenti/<slug>.md，运行 zhenti-data.mjs 生成 <slug>.data.js，用 guokao.mjs sync 同步到课程，最后校验。完成后告诉我加了哪些题、哪些题独立解与参考答案不一致。
```

## 注意

- 题型节点的 `count` 只统计「近三年」（2024、2025、2026 副省级）；2021、地市卷、模拟卷等其他行标签只进 `data.js` 的 `years` 与 `items`，不进 `count`。课程这边由 sync 从 `data.js` 取，两边口径一致。
- 题干、选项、答案数字都以原卷为准；提取工具丢的字要对照 `pdftoppm` 渲染的页面补回，补不全的在 `- 备注：` 说明。
- 学习者说「留作整卷」才用 `hold`；`hold` 的题不在课内作示范，只用于后面的模考。
- 不要手改 `<slug>.data.js`；要改，改 `<slug>.md` 再重新生成。
- 题库只留一份：不把题库文件、题图复制进课程目录或 skill 目录。

## 申论题目的条目写法

申论题没有选项，条目字段与选择题相同，含义按下面理解（现有写法见 `<题库>/zhenti/shenlun-quanjuan.md`）：`- 资料：` 写「给定资料 N、M（主题：……）」；`- 参考答案：` 写「机构参考答案（<文件名> 第 N 页）」；`- 独立解：` 写「自拟要点 N 条，见解法」；`- 一致：是` 表示自拟要点与参考答案大体对应，实质分歧写 `存疑`。`#### 解法` 分「审题」「自拟要点」「对照参考答案」三段。每套卷的给定资料全文另存 `<题库>/zhenti/shenlun-cailiao/<行标签>.md`。
