# 面试模板

这门课只有一个目标：学习者**懂这个主题的重点，并且能在面试里有条理地讲出来**。大纲突出面试官会深挖的部分，课中穿插面试题，最后一课把全课串成一条讲得出来的路线。

本文只写面试课和通用流程不同或多出来的地方，其余一律照 SKILL.md 和三份 references 走。下文标「覆盖」的条目与通用规则冲突，以本文为准。

## 什么时候读另外两个文件

| 时机 | 读什么 |
|---|---|

| 每个会话开始讲课之前（新开课和续学都算） | `lesson-guide.md`：面试课的分段写法、生长面板每课加什么、组件课四步、核心链路课、面试题的数量和题型、追问链、面试串讲和模拟面试 |

两份都在本文同目录。

## 开题

- **判断主题类型**，写进 `templateData.type`：
  - `system-design`：系统设计，如「设计一个实时计费系统」。
  - `knowledge`：知识点、八股，如「Go channel」「MySQL MVCC」。
  - `experience`：经历复盘，如「讲一次 SQL 调优」。

  一门课只记一个类型，取主体。类型之间可以借课：知识点或经历类主题在相关时也可以排非业务能力的课（并发控制、背压、降级）。
- **两个开题问题照常问**，但 `experience` 类不追问学习者的真实经历，见下一条。
- **`experience` 类用示范案例**：自己构造一个典型案例，背景、现象、指标都是示范数据。开题时在对话里明确说一次「这是示范案例，请换成你自己的经历」，建课时顶层写 `notice: "示范案例，请换成你自己的经历"`，页面会显示提示条。
- **不调研**：frontmatter 是 `research: skip`，`researched` 记 `"skipped"`，资料和延伸阅读照通用规则写。学习者明确要调研时照常调研。
- **上法（覆盖）**：不用另外判断，写进 `approach` 的就是这几件事：
  - 实践和检验都是课中的面试题，题型和数量见 lesson-guide.md。
  - 结课是「面试串讲」：最后一课固定是它，把全课串成面试里的讲述路线，可选一轮模拟面试。
  - 生长面板按类型取默认值：`system-design` 用 `diagram`；`knowledge` 用 `code`，偏原理、不适合写代码的用 `diagram`；`experience` 用 `timeline`，涉及 SQL 或配置改动时再加一个 `code`。细节见 outline-patterns.md。
- **大纲**：按 kickoff.md 的格式给出，骨架和每课一行怎么写按 outline-patterns.md。

建课时写入：`template: "interview"`，`templateData: { "type": "<主题类型>" }`，`experience` 类再写 `notice`。

## 讲课

### 面试题就是本课的检验

通用流程要求每课至少检验一次。面试课里，课中抛出的每一道面试题都是一次检验，记进本课的 `practice` 卡，参与「已掌握」和待回顾；不另外出检验题。每课出几道、出什么题型、放在哪里见 lesson-guide.md。

每道题的流程：

1. **发题**：按通用方式往本课 `practice` 卡追加一条，`q` 写题目全文，`rubric` 写评分标准，不写 `answer`，运行校验。然后在对话里抛题：「面试官可能会问：……」，接一句「你先试着答一下？也可以说"直接讲"。」，停下等作答。
2. **学习者作答**：按通用方式评分，补全 `yours`、`ok`、`why`、`answer`，按这一条处理 `mastered` 和 `review`。
3. **学习者说「直接讲」（覆盖）**：这就是跳过一道已发出的题，把这一条记为 `skipped: true`，然后直接讲解。跳过的处理照通用规则：不算掌握，不改 `mastered`，不加待回顾。题目待答时，「直接讲」「跳过」「直接讲完这课」都先按跳过这道题处理（记 `skipped: true`），再讲解；「直接讲完这课」另外表示本课剩下的内容连续讲完，段与段之间不再停。
4. **讲解**：不管答没答，都讲这道题的答题思路（先说什么、再说什么）→ 回答结构 → 参考回答（一段能照着说的话）。学习者答过的，先肯定答对的部分，再指出遗漏或结构问题，只评对错和缺口，不打分。
5. **课末写卡**：这道题的讲解写成一张 `problem` 卡，`title` 写「面试题」，`question` 是题目，`approach` 是答题思路和回答结构，`answer` 是参考回答。它跟在所讲的内容后面，不堆在课末。

追问链是同一个点连问三层：每一层是 `practice` 里单独的一条，一层一层发，每层都走上面的流程。整条链课末另写一张 `qa` 卡，标题「追问链：xx」，三条按顺序排；这条链不再写 `problem` 卡。

### 课末的卡片（覆盖默认标题，补充卡片约定）

- 每课至少 `points` 和 `quote`，`quote` 的 `title` 写「面试怎么讲」：一句面试里能直接说的话，而不是一般的总结。
- 每道单独的面试题一张标题为「面试题」的 `problem` 卡，每条追问链一张标题为「追问链：xx」的 `qa` 卡。`practice` 卡在发题时建好，课末不重写。
- 学习者插过话，照通用规则写 `questions`。
- 系统设计的**组件课**还要有：至少一张 `code` 卡放具体产物（接口定义、报文、schema、表结构、伪代码之一，`language` 不是 `mermaid`），一张 `compare` 卡放选型（候选方案、结论、什么情况下会换）。
- **核心链路课**还要有：`steps`（每一跳一句话）和至少一张 `code`（这次请求在各跳的报文和落库数据）。
- 卡片按讲的顺序排。`points` 写做法和依据（「幂等靠 `(account_id, event_id)` 唯一键」），不写口号（「要保证幂等」）。

### 生长面板

- `diagram` 的节点 `style`：服务和组件用 `box`（默认），存储和队列用 `pill`，外部系统和调用方用 `outline`，还没拆开的黑盒用 `ghost`。
- 每课优先加节点和连线，标注只放关键参数。核心链路课和面试串讲课各挂一条 `routes`，`lesson` 填本课 id。
- 版面在写大纲时按 outline-patterns.md 规划好；每课开课时加什么见 lesson-guide.md「生长面板每课加什么」。

## 结课：面试串讲

- 大纲最后一课固定是「面试串讲」，内容和卡片见 lesson-guide.md。
- **串讲课的检验由学习者选（覆盖「每课至少检验一次」）**：讲完串讲的内容后，用 `AskUserQuestion` 问一次，三个选项：
  - 「模拟面试一轮」：按 lesson-guide.md「模拟面试」做。
  - 「只把开场白和讲述路线讲一遍」：发一条 `practice`，`q` 请学习者按讲述路线讲一遍开场白和各段，`rubric` 列出路线上每段的关键要点并写明门槛；学习者讲完按通用方式评分。
  - 「跳过」：还没发题，没有条目要记，`mastered` 不变。
- **模拟面试**只走面试题流程的第 1、2、3 步：发题、评分或跳过。评分的结果可以先不讲；第 4 步的讲解并进全部问完后的统一点评；不写「面试题」`problem` 卡。
- `experience` 类：串讲开始时再提醒一次「这是示范案例，请换成你自己的经历」，并列出要替换的部分（背景、数字、你的角色）。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 面试题直接给出答案 | 先写进 `practice`、停下让学习者试答；说「直接讲」就记 `skipped: true` 再讲 |
| 面试题只写一张「面试题」卡，没进 `practice` | 发题时进 `practice`，讲解课末写成 `problem` 卡，两者都要 |
| 面试题之外又出一道检验题 | 面试题就是检验，不另外出 |
| 追问链三层一次抛出 | 一层一条 `practice`，一层一层问，课末整理成「追问链：xx」的 `qa` 卡 |
| 模拟面试每问一题就讲一次参考回答 | 只发题、评分或跳过，讲解并进全部问完后的统一点评 |
| 大纲最后一课不是面试串讲 | 最后一课固定是「面试串讲」 |
| `experience` 主题追问学习者的真实经历 | 构造示范案例，写 `notice`，开题和串讲各提醒一次 |
| 组件课只有结论，`code` 卡是 mermaid 流程图 | 每个组件课至少一份能照着写的产物，写成非 mermaid 的 `code` 卡 |
