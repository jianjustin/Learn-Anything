# 讲课细则

每一步改数据时，对照 data-format.md「写入清单」里对应的阶段。

## 1. 一段讲多少

- 一段只讲一个点：一个概念、一个机制、一个取舍、一个步骤、一个例子。
- 约 300 字以内，代码块和表格不计入；最多配一张简图（见第 10 节）。
- 结构：一句结论 → 两三句展开（为什么、怎么做、举个具体的例子或数字）→ 段末停下。
- 段末停下的措辞要轮换，例如：
  - 「到这里有疑问吗？没有的话我接着讲 xx。」
  - 「你觉得 xx 会带来什么问题？想一想再往下。」
  - 「下一段讲 xx，继续吗？」
- 学习者说「直接讲完这课」时，在对话里连续讲完剩下的段，每段一个小标题，讲完再停。内容要在对话里讲出来，不能只写进卡片。
- 每讲完一段更新 `resume.note`（一句话：讲到哪、下一步讲什么）和 `updatedAt`。

示例（一段）：

```text
**为什么央行加息会让股市下跌？**

结论：加息同时抬高了企业的融资成本和投资者要求的回报率，两头都压低股票的估值。

  加息 ──▶ 贷款利率↑ ──▶ 企业利润↓ ──┐
    │                                ├──▶ 股价↓
    └──▶ 无风险收益率↑ ──▶ 折现率↑ ──┘

比如国债收益率从 2% 升到 4%，一只每年分红 3% 的股票就不如国债有吸引力了，资金会流出，直到股价跌到分红率重新有竞争力。

这里能跟上吗？下一段讲为什么有时加息股市反而涨。
```

## 2. 插话处理

- 先直接回答，篇幅和一段讲解差不多。
- 与本课相关：回答后接回原来的位置（「回到刚才……」）。
- 偏离本课：简要回答，然后说「这个在第 N 课 xx 会细讲」；后面没有对应的课时，说「我先记进待回顾」，往 `review` 末尾加一条。插话产生的待回顾条目一律写 `"lesson": null`：它不是哪一课的检验缺口，回顾答上来也不该让哪一课变成已掌握。
- 每次插话都记下问题和回答要点，课末写进本课的 `questions` 卡：`q` 是学习者原话的精简版，`a` 是一两句话的回答要点。

## 3. 检验：出什么题

每课至少一次检验，检的是这一课的核心，不考边角细节。一次只发一道题。

### 选形式

| 形式 | 适合什么课 | 例子 |
|---|---|---|
| 复述 | 概念、原理、框架类的课 | 「用你自己的话讲讲为什么加息会压低股价，像讲给一个没学过的朋友听。」 |
| 简答 | 有明确要点的辨析、比较、因果 | 「名义利率和实际利率差在哪？什么时候两者会背离？」 |
| 案例分析 | 要把知识用到具体情境的课 | 给一段真实或构造的情境，问「你会怎么判断，依据是什么」 |
| 做练习 | 有标准做法的计算、推导、操作、写代码 | 一道计算题，或「写一个函数实现……」 |
| 推进项目 | 课程有贯穿全程的项目 | 「给项目加上……功能，要求……」 |

上法里定了默认形式；某一课更适合别的形式就换。

### 主观题与客观题

- **主观题**：答案是一段表述，对错要对照要点判断，如复述、简答、案例分析。必须写 `rubric`。
- **客观题**：答案唯一或能直接运行验证，如计算结果、选择、能跑的代码。`rubric` 可以省略。

### 评分标准怎么写

评分标准要让一个只看得到题目、评分标准和答卷的人能独立判出对错。写法：列出要点，写明门槛。

- 好：「答出以下三点中的至少两点：① 加息抬高企业融资成本、压低利润；② 加息抬高折现率、压低估值；③ 无风险资产收益上升，资金从股市流出。」
- 不好：「理解加息对股市的影响。」——看不出什么算理解。
- 不好：「答得完整、有条理。」——评的是表达，不是内容。

每个要点写成一个能判断有没有答到的意思，不写关键词。没写门槛时，评分方会要求全部要点都答到。

评分标准发题时就写进数据，但页面在这一条有 `yours` 或 `skipped: true` 之前不显示它，学习者作答或跳过之后才看得到。在对话里发题时也只发题目，不念评分标准。

### 发题的流程

1. 把题目和评分标准写进本课 `practice` 卡的一个新条目：`q` 写题目全文，`rubric` 写评分标准。不写 `answer`：页面一有 `answer` 就显示。
2. 运行校验。
3. 在对话里发题，然后停下等作答。学习者可以说「跳过」或「直接评」。
4. 学习者想往下走又没明说跳过时（「先不做了」「下次再说」），用 `AskUserQuestion` 问一次：作答，还是跳过这题。

## 4. 检验：评分

### 主观题交给 `answer-grader`

用 Agent 工具调用，子代理类型是 `learn-anything:answer-grader`。提示只有下面三项，按这个顺序，标签照抄：

```text
- **题目**：<与 practice 条目的 q 一字不差>
- **评分标准**：<与 practice 条目的 rubric 一字不差>
- **学习者的原话**：<学习者的回答，原样粘贴>
```

「学习者的原话」必须是最后一项：评分方把这个标签之后直到结尾的全部内容当作答卷。粘贴学习者的回答时一字不改：不纠正错别字，不补全，不翻译，不删掉看似无关的话。多行的回答原样换行接在标签后面。

评分方只回一个 JSON 对象：

```json
{"mastered": false, "hits": ["命中的要点"], "misses": ["缺失或讲错的要点"], "feedback": "给学习者的一两句话"}
```

### 当场判的三种情况

- 客观题、能运行验证的练习：直接对照正确结果判。代码能运行就运行，不能运行就请学习者贴出运行结果。
- 学习者说了「直接评」。
- 评分子代理用不了：Agent 工具报告这个子代理类型不存在、调用失败，或者回复去掉可能包着的代码块标记后仍不是合法 JSON、缺少这四个字段。

当场判主观题时用和评分方一样的标准：把评分标准拆成要点，逐条看学习者的意思有没有答到，按门槛判是否掌握。表达流畅不加分，口语化和错别字不扣分。

### 写回 `practice` 条目

| 字段 | 写什么 |
|---|---|
| `yours` | 学习者的原话，一字不改 |
| `ok` | 评分方的 `mastered`；当场判的用你的判定 |
| `why` | 只在没掌握时写：把 `misses` 用「；」连起来，或你判出的缺口 |
| `answer` | 你写的参考答案：一段能照着说或照着做的完整回答 |

写完运行校验。

### 告诉学习者

先转述评分方的 `feedback`（当场判的就自己说一句），再点出答到了哪些、缺了哪些，最后讲参考答案的思路。只评对错和缺口，不打分。

### 掌握与待回顾

每评完一条，只按这一条处理：

- 这一条通过，并且 `review` 里没有指向本课的条目：本课 `mastered` 设为 `true`。
- 这一条没通过：往 `review` 末尾加一条 `{ "lesson": "<本课 id>", "text": "<缺口>" }`，并把本课 `mastered` 设为 `false`。`text` 写成下次能直接拿来问的样子，如「说出加息压低股价的两条路径」。
- 学习者说「跳过」：题目已经发出的，把这一条记为 `skipped: true`，不写 `yours` 和 `ok`；还没发题就没有条目要记。跳过不算掌握，不改 `mastered`，不加待回顾。
- 讲完就推进：没掌握也照常往下讲，缺口交给待回顾。

## 5. 卡片和出处

### 课末写哪些卡片

- 至少 `points`（本课要点）和 `quote`（一句话总结）。
- 学习者插过话：`questions`。
- `practice` 在发题时就已经建好，课末不重写。
- 其余按内容选：对比用 `compare` 或 `table`，流程用 `steps`，代码和产物用 `code`，留给学习者想的问题用 `problem`，常见追问用 `qa`，清单用 `chips`。
- 卡片按讲的顺序排。
- `points` 写具体的做法、依据和数字，不写口号。写完每条问自己：去掉这句，学习者少知道了什么？

### `refs` 只写真实出处

`refs` 列出这张卡片的内容出自哪些资料，资料 id 必须在 `resources` 里。

- 卡片内容确实来自某份资料（你讲的就是这本书这一章的内容，或调研报告指向的那份资料），才写它的 id。
- 凭你自己的知识写的卡片不写 `refs`。`researched` 为 `"yes"` 时，页面会把这样的卡片如实标成「未核对」。这是正常的，也是诚实的：不要为了显得有出处而挂上 `refs`。
- `questions`、`practice`、`note` 三种卡片记录的是学习过程，页面不显示它们的来源标记，不写 `refs`。

## 6. 课末

1. 在对话里给 3–5 条小结。
2. 按 data-format.md「课末」清单写入：本课卡片、本课设为 `done`、下一课设为 `current`、`resume` 指向下一课。下一课是顺序上在本课之后的第一门 `todo` 的课；本课之后没有 `todo` 的课时，取整个列表里第一门 `todo` 的课；都没有就是课程讲完了，`resume` 留在本课并说明讲完。已经 `done` 或 `skipped` 的课不会被改回 `current`。
3. 运行校验。
4. 告诉学习者页面已更新，问是否进入下一课。
5. 课程讲完了（没有下一课）时：`resume.lesson` 留在本课，`note` 写「全部课程已讲完」；告诉学习者课程完成，还有几条待回顾、几门课没掌握，说「继续学习」可以回来回顾，也可以随时要求补测（见第 8 节）。

## 7. 续学回顾

读完 `course-data.js` 后，用两三句话回顾，再给一次课程页的绝对路径：

```text
我们在「宏观经济学入门」学到了第 4 课「货币政策」（已讲 3 / 9 课，已掌握 2 课）。
上次讲到：加息怎样传导到股市已经讲完，下一步讲量化宽松。
待回顾还有 2 条，先花两分钟过一下。课程页：/Users/.../macro-economics/course.html
```

然后：

1. **回顾**：`review` 不为空时，取最前面的一两条（数组越靠前越早），一次问一条，让学习者凭记忆回答。学习者说「跳过回顾」时直接到第 2 步。
   - 答上来（对照条目写明的缺口当场判）：从 `review` 删掉这一条。这条的 `lesson` 不是 `null`，并且 `review` 里没有别的条目指向这一课时，把这一课的 `mastered` 设为 `true`。`lesson` 是 `null` 的条目（插话记下的）答上来只删条目，不改任何课的 `mastered`。
   - 没答上来：简要重讲这个点，条目保留。
   - 每处理完一条就写入并校验。
2. **从断点继续**：
   - `resume.lesson` 那一课是 `current`，并且它的 `practice` 里有既没有 `yours` 也没有 `skipped` 的条目：这是发出后还没作答的题，把 `q` 原样再发一次，等作答。记了 `skipped: true` 的题不再发。
   - `resume.lesson` 那一课是 `current`：按 `resume.note` 从断点接着讲。
   - `resume.lesson` 那一课已经是 `done`：把它当作本课，按第 6 节里「下一课」的定义找到下一课，从那一课开课。课程已经讲完时告诉学习者，问要不要补测没掌握的课。

## 8. 补测

检验被跳过的课、没通过的课和迁移来的课都还没掌握。学习者可以随时要求对任何一门 `done` 的课补测一次：

1. 按第 3 节出一道检验这一课核心的题，写进**那一课**的 `practice` 卡（没有就新建一张），不写参考答案，运行校验，然后发题。
2. 按第 4 节评分，写回这一条的 `yours`、`ok`、`why`、`answer`。
3. 通过，并且 `review` 里没有指向这一课的条目：把那一课的 `mastered` 设为 `true`。没通过：往 `review` 末尾加一条 `{ "lesson": "<那一课 id>", "text": "<缺口>" }`，`mastered` 保持 `false`。
4. 补测不改 `resume`、课的 `status` 和别的课；写入后运行校验，再回到原来讲到的地方。

## 9. 调整大纲

1. 在对话里给出调整后的大纲（可以只列变化的部分）。删除、重排、重开属于大改动：说明影响，用 `AskUserQuestion` 得到确认后再改文件。
2. **插入**：新课用一个不重复的 id，插到 `lessons` 的对应位置，`status: "todo"`，`mastered: false`，`cards: []`，按需写 `readings`。
3. **删除**：先找出引用这一课 id 的地方：生长元素的 `since`、`until`，`routes[].lesson`，`resume.lesson`，`review[].lesson`。逐个改挂到相邻的课或删掉，告诉学习者，再删课。
4. **跳过**：`status: "skipped"`，保留在数组里。
5. **重排**：只调整 `lessons` 的顺序。生长元素按课程 id 而不是序号引用课，所以位置会跟着走；但要检查每个 `until` 仍在对应的 `since` 之后。
6. 已学课程的卡片和生长元素不改。
7. 写入后运行校验。

## 10. 对话里的图

终端不渲染 mermaid。对话里的图保持短小：

- ASCII 框图（首选），像第 1 节示例那样；
- 或者不超过约 8 行的 mermaid 源码，终端里只显示源码，所以要短。

完整的图放在课程页的 `diagram` 面板里，提醒学习者：「完整的图看课程页，本课新增的部分已经高亮。」
