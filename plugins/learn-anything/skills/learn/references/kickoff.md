# 开题细则

开题的目标是一份学习者认可、有出处的大纲。顺序是：提问 → 匹配模板 → 调研 → 定上法 → 给出大纲 → 确认 → 建课。确认之前不创建任何文件。

## 1. 两个开题问题

在对话里一次问完，编号列出，不用弹窗（这是开放问题）：

1. **为什么学、想学到什么程度。** 给一两个例子帮学习者说具体，例如「能看懂上市公司财报并自己算几个关键指标」「能独立用它写一个小工具」「能在面试里讲清楚」。
2. **已有哪些基础。** 学过什么相关的东西、做过什么；手头有想用的书、课程或链接，也请一起说。

请求里已经说清的那一问就不再问，两问都说清了就直接进入下一步。回答太笼统、没法据此决定深度时，追问一次；还是笼统就按常见情况假设，并在大纲的上法说明里写明你的假设。

这两问的答案分别写进 `mission`：`why`（为什么学）、`target`（学到什么程度）、`background`（已有基础）。

## 2. 调研任务书

先告诉学习者「我先查一下这个主题公认的课纲和教材，大约要几分钟」，再用 Agent 工具调用，子代理类型是 `learn-anything:course-researcher`。提示按下面六项给出，标签照抄，没有内容的项写「无」：

```text
- **主题**：<主题>
- **为什么学**：<学习者的回答>
- **学到什么程度**：<学习者的回答>
- **已有基础**：<学习者的回答>
- **学习者指定的资料**：<书名、课程或链接，逐个列出；没有写「无」>
- **讲课语言**：<学习者使用的语言>
```

子代理交回一份 Markdown 报告，固定五节：`## 资料清单`、`## 大纲草案`、`## 上法建议`、`## 资料缺口`、`## 未核实`。报告给你看，不原样转给学习者。

## 3. `researched` 取哪个值

| 取值 | 什么时候用 | 学习者看到什么 |
|---|---|---|
| `"yes"` | 调研子代理交回了报告，资料清单里至少有一份资料，你据此写了大纲 | 卡片逐张显示来源，没有 `refs` 的卡片显示「未核对」 |
| `"no"` | 想调研但做不到：Agent 工具报告这个子代理类型不存在、调用失败、没有联网能力，或者报告的资料清单是「无」。这时凭你自己的知识出大纲 | 页面提示「大纲未经资料核对」；你也要在对话里说一句 |
| `"skipped"` | 套用的模板声明 `research: skip`，或者学习者说不用调研 | 不显示提示，也不显示逐卡来源 |

### 没有调研报告时的资料规则

`researched` 是 `"no"` 或 `"skipped"` 时，手里没有核对过的目录，资料按下面的规则写：

- 资料清单只放学习者指定的资料和你确信存在的资料，每一项的 `note` 末尾加「（未能核实）」；没有就为空数组。
- 每份延伸阅读的 `where` 一律写「章节未核对」。章节号只能来自核对过的目录，不凭记忆写。
- 大纲在对话里给出时，延伸阅读同样写「章节未核对」。

## 4. 把调研报告变成课程数据

### 资料清单 → `resources`

报告「资料清单」表格的每一行变成一项：`id` 照抄；`kind` 取「类型」；`title` 取「标题」；「作者」「链接」不为空时写进 `author`、`url`，为空时省略这个字段；`note` 取「说明」，再按「核实情况」处理：

| 核实情况 | 处理 |
|---|---|
| 目录已核对 | 原样写入 |
| 仅核实存在 | 写入，`note` 末尾加「（章节未核对）」 |
| 未核实（只会出现在学习者指定的资料上） | 写入，`note` 末尾加「（未能核实）」 |

只出现在报告「## 未核实」一节、不在表格里的资料，不进课程数据。给出大纲时在对话里告诉学习者这些资料没能核实、所以没有列入。

### 大纲草案 → `lessons`

草案每行是 `序号. 标题 —— 一句话说明；延伸阅读：<资料 id> <章节>；（可选）`。

- 草案是起点，按学习者的目标、基础和套用的模板增删合并。已经会的内容压成一课复习或去掉，目标之外的内容标可选。
- 每课一个 `id`：英文 kebab-case，取自标题的简写，全课程唯一，创建后不再改。
- 「（可选）」→ `optional: true`。
- 每份延伸阅读变成 `readings` 里的一项 `{ "resource": "<资料 id>", "where": "<章节>" }`：
  - 草案给了章节，并且这份资料是「目录已核对」：`where` 照抄章节。
  - 草案只写了资料 id，或者这份资料不是「目录已核对」：`where` 写「章节未核对」。
  - 延伸阅读是「无」：`readings` 为空数组。
- `readings` 里的资料 id 必须在 `resources` 里。

### 其余三节

- **上法建议**：作为你定上法的参考（第 5 节），不照抄。
- **资料缺口**：给出大纲时告诉学习者哪些课没找到可靠资料，这些课由你凭自身知识讲。
- **未核实**：见上面的资料清单规则。

### `refs` 留到讲课时写

`refs` 是卡片的出处，讲课写卡片时才填，规则在 lesson-guide.md。开题时只建好 `resources`，让后面的 `refs` 有资料可引。

## 5. 定上法

上法不设课型、不给选项表，由你按主题和学习者的目标判断。写进 `approach` 的是两到四句自由文本，覆盖下面四件事；在大纲里给出时要带上理由。

1. **有没有实践，什么形式。** 学了要会做的主题要有实践：做题、写代码、做小项目、分析案例、模拟操作。纯理解类的主题可以不设实践，靠复述和简答检验。实践只能用无风险的方式：涉及金钱、健康、安全的主题用模拟、纸面推演或历史案例，不让学习者真实操作。
2. **怎么检验。** 每课至少一次。默认用哪种形式（复述、简答、案例分析、做练习、推进项目），什么样的课换别的形式。具体怎么出题见 lesson-guide.md。
3. **怎么结课。** 最后一课做什么：综合项目、综合案例分析、一次覆盖全课的测验、把全课串起来讲一遍。按学习者的目标选：目标是能做事就用项目或案例，目标是能讲清楚就用串讲。
4. **是否启用生长面板，用哪种。** 只在课程有逐课演进的东西时启用，一门课一般最多一两个：
   - `diagram`：一张结构图逐课长出新的方框和箭头，如系统架构、概念之间的关系、一条流程。
   - `code`：一份代码或文本逐版演进，如贯穿全课的小项目。
   - `timeline`：按时间排列的事件，可带指标条，如一次排查或复盘的过程、一段历史。
   - 理论为主、各课之间没有共同演进对象的课程不启用，`growth` 为空数组。

套用了模板时，以模板规定的上法为准。

## 6. 大纲在对话里的格式

按这个顺序给出，没有的部分省略：

```text
本课套用「<模板名>」模板（不需要的话告诉我，就按通用方式开课）。

上法：<两到四句：实践、检验、结课、生长面板，各带一句理由>

资料：
- 《<标题>》<作者> —— <覆盖什么、什么时候看>
- ……

大纲（共 N 课）：
1. <标题> —— <一句话说明>（延伸阅读：《<标题>》<章节>）
2. <标题> —— <一句话说明>（延伸阅读：无）
3. <标题> —— <一句话说明>（可选）
……

没能核实、所以没有列入的资料：<逐个说明>
没找到可靠资料的部分：<哪几课，由我凭自身知识讲>

拟定的课程名（slug）：<slug>
```

- 一课一行。延伸阅读写资料名而不是资料 id；章节没核对的写「章节未核对」。
- `researched` 是 `"no"` 时，在「资料」之前加一句「这份大纲没有经过资料核对」。
- 给出大纲后用 `AskUserQuestion` 问一个问题，header 写「大纲」，两个选项：「确认，开始建课」和「我要调整」。学习者选调整或直接打字提意见时，改好整份大纲再问一次。

## 7. slug 规则

- 英文 kebab-case：小写字母、数字和连字符，形如 `^[a-z0-9]+(-[a-z0-9]+)*$`，如 `macro-economics`、`us-stock-swing-trading`。
- 两到四个词，取自主题，看名字就知道是哪门课。中文主题用英文意译，不用拼音。
- 给出之前对照 `index-data.js` 避开已有的 slug 和 `dir`。

## 8. 建课

学习者确认大纲后：

1. 运行建课命令（SKILL.md「路径约定」），记下它输出的课程页绝对路径。退出码 1 时读 ✗ 后面的信息：slug 不合法就改 slug；课程目录已存在就换 slug 并告诉学习者；其他错误（比如 `index-data.js` 读不懂或写不进去）就停下，把信息原样告诉学习者，不要手改 `index-data.js`，也不要反复换 slug 重试。
2. 写 `<课程目录>/<slug>/course-data.js`（新建的课 `dir` 等于 slug），字段按 data-format.md 的「建课」清单，内容来自开题：
   - `mission` 来自两个开题问题；`approach` 来自第 5 节；`researched` 来自第 3 节；`template` 是套用的模板名或 `null`。
   - 这门课是一组系列课中的一门（学习者把一个大目标拆成了几门课，或者说「这是 xx 系列的下一门」）时写 `series`：`name` 是系列名，几个字，看名字就知道是哪组课；`order` 是这门课在系列里的序号。系列里已有课时，先读它们的 `series.name` 照抄，不另起名字。整个系列有需要交代的事（各门课怎么分工、建议的学习顺序与序号不同）时，写进系列里 `order` 最小的那门课的 `series.description`，总览页显示为一栏默认折叠的「系列说明」；新增一门课改变了这些内容时，改那一门课里的说明，不在别的课里再写一份。
   - `resources` 和每课的 `readings` 来自第 4 节。
   - `lessons` 按确认后的大纲，第一课 `current`，其余 `todo`，全部 `mastered: false`、`cards: []`。
   - `growth` 按第 5 节建好面板骨架，元素留到各课开课时再加。
3. 运行校验命令，有错误先修好。
4. 打开课程页：macOS `open <路径>`，Linux `xdg-open <路径>`，Windows `start "" "<路径>"`。命令失败时把绝对路径给学习者，请他自己打开。同时告诉他总览页是 `<课程目录>/index.html`。
5. 开始第一课。
